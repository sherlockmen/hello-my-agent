# 第 35 章：用固定任务验证 Agent 能力

[全书目录](/content/README.md) · [35.1 固定任务与离线回放](/content/chapter-35-agent-evaluation/01-fixed-tasks/README.md) · [35.2 故障与终端回归](/content/chapter-35-agent-evaluation/02-failure-and-terminal/README.md) · [35.3 显式运行真实模型评测](/content/chapter-35-agent-evaluation/03-live-model-benchmark/README.md) · [练习与答案](/content/chapter-35-agent-evaluation/EXERCISES.md)

前一章让我们看见一次运行在哪里停下、能否重试，以及已经发生的操作。现在还有一个问题：修改了 Agent 的核心之后，它是否仍能把同一个任务做好？手动输入一次“修好加法”，看到一句“测试通过”，只能证明界面显示了这句话。模型可能没有改文件，也可能把测试改得永远通过。

这一章把“演示看上去成功”换成一份可以重复核对的实验。我们固定有缺陷的项目、任务要求、允许修改的文件和最终检查；每次从新的临时目录开始。Agent 仍走原来的模型接口、权限、工具和消息回传，评测器在任务结束之后检查实际文件与测试结果。

我们先把模型回复固定下来，排除网络和随机选择，让核心回归能够重复运行；接着主动制造拒绝、工具失败、取消和误改，核对停止以后留下什么；最后开放一个明确选择才会调用真实模型的入口。真实模型沿用相同任务和判分，报告额外记录模型身份、耗时、服务商报告的用量和运行平台。

| 小节 | 我们动手做什么 | 用什么判断完成 |
| --- | --- | --- |
| 35.1 | 把固定模型回复接入真实 Agent Loop，在临时项目里读、改、测 | 正确计算，受保护文件没变，真实测试得到零退出码 |
| 35.2 | 故意让模型空口报喜、请求被拒、读取出错或修改后取消；检查终端机制 | 每个样本按自己的预期判定，取消后的文件另行核对 |
| 35.3 | 用户显式选择在线评测，输出可比较的报告 | 仍由客观检查判任务结果；未知费用与未验证平台如实保留 |

本章不会把一组小任务的通过率称为“所有 Agent 能力”。固定回放主要检验程序能否正确执行已经给出的决定，真实模型评测才把“模型会怎样决定”加入观察。两种实验各有作用，报告必须保留这一区别。
