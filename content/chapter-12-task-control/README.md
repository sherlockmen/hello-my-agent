# 第 12 章：计划、执行与运行中干预

[12.1 计划与执行](/content/chapter-12-task-control/01-plan-mode/README.md) · [12.2 任务清单](/content/chapter-12-task-control/02-task-list/README.md) · [12.3 澄清问题](/content/chapter-12-task-control/03-clarify-questions/README.md) · [12.4 补充与打断](/content/chapter-12-task-control/04-live-input/README.md) · [12.5 编辑和撤回队列](/content/chapter-12-task-control/05-manage-queue/README.md) · [练习与答案](/content/chapter-12-task-control/EXERCISES.md)

第十一章把终端变成能够编辑草稿、浏览历史和保留阅读位置的工作区。接下来要处理的不只是输入文字：我们可能先想审阅改法，做到一半才发现需求没说清，还可能临时补一项测试，或者决定先停下。

本章让这些决定进入 Agent 的任务过程。学完后，我们应能解释一份方案怎样帮助人决定实施、清单为什么可以完整拒绝无效更新、用户答案怎样接回原问题，以及运行中写下的要求何时成为模型的下一份输入。遮住完整实现，改变一次提交或收取的先后，我们也应该能推断会留下什么状态。

## 沿一个小项目，把不同决定说清楚

[demo-project](/content/chapter-12-task-control/demo-project/_index.md) 只有加法实现 `src/add.mjs` 和测试 `test/add.test.mjs`。教学情境假设返回表达式误写为 `left - right`：输入 `2, 3` 会得到 `-1`，测试要的是 `5`。错误很小，便于把注意力留给人的决定与程序怎样接住它。实操时先核对实际文件；如果已经修好，就直接调查现状和验证，后续小节不要求重复制造错误。

首先，我们希望知道“为什么错、改什么、怎样验证”。12.1 用 Plan 交付基于代码事实的方案，并让本地阻止提前修改。用户审阅后，切到 execute，再明确提交实施要求。计划是可审阅的普通回答，切模式不会自动执行它。

实施以后，关心的问题变成“当前走到哪一步”。12.2 将检查、修复和测试表示为一份带状态的清单。模型报告进展，本地校验并整体接受这份数据，界面持续显示它。清单不负责执行，也不能代替测试证据。

若要求加法接受数字字符串，`"1"` 与 `"2"` 应得到数字 `3`，非法字符串却未规定报错还是返回 `0`，缺少的是用户的规则。12.3 通过 `ask_user` 提问、等待，并把答案作为原调用的结果交回。我们得到继续实现的条件，后续文件修改仍需按已有规则审批。

运行中想到“请测试两个负数相加”，这项补充不推翻原任务。12.4 让 Enter 先保存到当前任务的队列，等完整回应与本批工具结果处理完，再在后续模型请求前收取。若方向改成“先别修改，只解释原因”，Ctrl+S 则先停下旧任务、等它本地收尾，才启动新任务。

最后，待处理文字仍可能需要整理。12.5 用稳定 ID 和独立编辑稿修改队列项，保存时再检查原项是否存在。还在队列里，可以编辑或撤回；已收取进本地消息，即使请求尚未发出，也要另发修正，不能再从队列改掉旧要求。

## 本章新加的对象，怎样接到已有循环

一项任务（`run`）从用户提交开始，到 Agent 停下结束，可以包含多次模型请求。每次模型返回工具安排，本地执行并保存对应结果，再带着材料请求模型继续判断。本章围绕这条循环增加了不同对象，它们的含义不能混为一谈。

| 对象 | 保存什么、由谁改变 | 它帮助我们决定什么 |
| --- | --- | --- |
| 本次任务的模式 | 本地入口选定 Plan 或 execute，整项任务使用同一值 | 当前阶段允许调查，还是允许提出实施动作 |
| 会话清单 | 模型提交完整步骤与状态，本地全部校验后替换 | 模型最后报告工作推进到哪里 |
| 一次澄清等待 | 当前问题、答案返回入口与结束标记 | 哪个未知规则正在等待用户决定 |
| 待处理输入队列 | 用户补充的文字、稳定 ID 和所属任务 | 哪份要求还没被核心收取 |
| 旧任务的 `done` | 代表执行、事件消费与界面状态清理结束的 Promise | 本地什么时候可以启动替代任务 |

模式与权限分别判断阶段能力和具体调用许可；回答澄清不会批准修改。清单表示模型报告，队列保存用户要求；清单标完成不会证明测试通过。取消让本地停止并记录实际情况，已经完成的文件改变不会因此回滚。

## 从哪里继续，怎样验证

起点是 [11.5](/content/chapter-11-terminal-workbench/05-terminal-layout/README.md) 的完整 `src/`。[第十一章练习](/content/chapter-11-terminal-workbench/EXERCISES.md) 是独立状态实验，不改变正式实现；本章五节依次沿用上一节，在“动手构建”中列出新增文件和明确替换范围，未列出的内容继续保留。

每节 `src/` 是我们用 TypeScript 构建的 Agent；`demo-project` 的 `.mjs` 文件是交给它操作的练习项目，采用很小的 JavaScript 示例以便直接运行测试。两者用途不同，跟写时修改的是前者，手动请求里让 Agent 检查的是后者。

运行位置以各节说明为准，配置沿用仓库根目录 `.env`。Agent 仍以教程仓库为项目根，所以发送任务时写出 `chapter-12-task-control/demo-project/...` 完整相对路径。正文与图中的 `add.mjs` 省略这段前缀。构建与注册只准备本地程序，启动并发送任务之后才调用模型。

完成 12.5 后，做[章末练习](/content/chapter-12-task-control/EXERCISES.md)：先预测一次操作改变哪个对象，再用真实工具和本地模型替身核对状态与请求。在完整配套仓库根目录，还可以运行本章固定检查：

```bash
npm run check:12
```

固定输入检查验证内部顺序，手动运行观察真实终端、焦点与模型行为。实际模型的措辞和工具安排可能不同；一次回答看起来成功，不能代替对清单、调用结果和请求内容的检查。
