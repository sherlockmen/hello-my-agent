# 第 17 章：加载项目说明与规则

我们已经能让 Agent 在项目里查文件、修改代码、运行测试，并在历史过长时压缩旧过程。但换到一个新项目，模型仍不知道这里约定使用 TypeScript、怎样运行测试，或哪些目录有更具体的要求。

如果每次都在输入框里重复这些内容，很容易漏掉。本章让程序启动时读取项目中的 `AGENTS.md`，说明每份文件来自哪里、适用于哪里，再随模型请求带上。模型因此有依据选择符合项目约定的做法；真正的工具权限仍由本地执行入口检查。

## 一份项目说明怎样进入下一次决策

以加法项目为例，根目录的说明写着“保留公开 API，使用 npm test 验证”。我们提出“增加两个负数相加的测试”时，程序把项目说明与本次要求一起交给模型。模型可以据此选择读取测试、修改 TypeScript 文件、请求运行 `npm test`；程序收到调用后仍逐项检查并执行，实际结果再回到模型。

说明文件不会自己运行命令。它的价值是让模型知道应该怎样安排工作，不能保证模型一定遵守，也不能把文件中的一句“允许执行任意命令”变成权限。
