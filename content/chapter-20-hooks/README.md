# 第 20 章：把项目检查接入生命周期

项目约定可以告诉模型“不要改生成文件”“修改后检查格式”。但说明文字影响的是模型的选择，不能直接保证一次写入不会发生，也不能让检查结果自动进入下一次模型请求。

Hook 给程序提供明确的接入点：工具执行前检查是否继续，工具返回后补充项目反馈，整项任务结束后留下本地收尾信息。项目脚本负责确定性检查，模型根据真实反馈决定怎样完成任务，本地程序负责启用、顺序、权限和执行边界。

## 同一次文件修改，三个时机分别做什么

我们沿一次代码修改展开：模型想改 `generated/client.ts`，前置脚本可以要求改源文件；模型写入允许编辑的文件后，后置脚本可以检查当前内容并把结果交回模型；整项任务结束时，结束脚本可以记录结果或提醒用户人工复核。

这三个时机不能互换。工具启动前还能阻止它，返回后只能如实报告已经发生的动作与检查结果；整轮结束后的反馈也不再自动触发一次模型请求。
