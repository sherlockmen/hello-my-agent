# 第 16 章：自动压缩并继续任务

第 15 章让 Agent 知道下一份请求能不能装进上下文窗口。超限时，程序保留历史并停止。这保证了不会带着一份明知过大的请求继续发送，但我们正在修复的加法任务也会因此停在半路。

本章让 Agent 在这个位置多做一步：把较早的讨论和工具结果整理成短摘要，保留当前要求和近期完整记录，再检查整理后的请求是否放得下。成功以后，模型收到摘要、要求和最新结果，继续决定下一步。

## 压缩的是下次发给模型的内容

假设任务是“修复加法，并测试两个负数相加”。前面已经读取过几版源码，运行过几次测试。每次都重新发送早期的长日志，会挤占新的输入空间；但直接删掉前半段，又可能丢掉“必须覆盖负数”的要求，或留下一条找不到对应调用的工具结果。

因此，本章保留两份用途不同的对象：

| 对象 | 保存什么 | 谁会使用 |
| --- | --- | --- |
| 完整历史 | 已取得的用户消息、模型回答、工具调用与结果 | 会话保存、恢复、分支和本地检查 |
| 下次请求的消息视图 | 旧内容摘要、原始用户要求、近期完整消息组与当前任务清单 | 下一次模型决策 |

摘要没有覆盖或删除完整历史。它只是让后续请求可以用更短的材料接着工作。摘要也可能遗漏或理解错误，所以“摘要已生成”不能证明原任务已完成；是否修改正确、测试是否通过，仍要看后续工具结果。
