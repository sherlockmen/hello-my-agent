# 第 13 章：保存、查找与恢复会话

第 12 章让我们能在任务执行中审阅方案、回答问题、补充要求，也能整理还没被收取的队列项。这些内容都有了明确的归属，但会话仍保存在当前进程的内存里。退出程序后，再次启动的 Agent 不知道上次讨论过什么、哪些工具已经执行、哪条补充还在等待。

这一章从保存开始，逐步回答两个问题：怎样留下足够的会话记录，怎样把可信的记录装回一个能够继续工作的 Agent。

## 先分清会话与工作区

假设 Agent 已经读取 `add.mjs`，检查过两个负数相加，并在对话里说明了结果。会话记录需要留下用户要求、模型发起的工具调用和工具返回值，后续模型才能理解“已经检查过什么”。与此同时，`add.mjs` 本身仍是工作区里的文件；保存工具返回值并没有把它的内容另存为一个可回滚的版本。

因此，恢复会话要解决的是让 Agent 接上已有讨论。恢复文件要解决的是把工作区改回某个版本，它会在后面的文件检查点章节展开。两者都可能影响继续任务，但不能互相替代。

## 本章路线

我们先建立可以检查的写入结果，再增加读取与使用这些结果的能力。当前交付到 13.1，后续小节会按下面的学习问题继续展开。

| 学习问题 | 本章要建立的能力 |
| --- | --- |
| [13.1 会话保存](/content/chapter-13-session-persistence/01-save-session/README.md) | 明确保存对象与完成时机，把会话快照依次追加到文件 |
| 文件里哪些记录可以使用 | 检查格式与版本，从有效记录中取得能够解释的状态 |
| 怎样继续上次的讨论 | 把状态装回会话，保留已经发生的工具调用与结果，避免因恢复而重放工具 |
| 怎样识别正在使用或被中断的会话 | 处理会话锁与中断标记，让使用权和结束状态有明确依据 |
| 怎样找到并管理会话 | 增加列表、命名、搜索、导出，并核对会话记录的工作区信息 |

第一节使用 JSONL：每一行保存一条 JSON 记录。它让记录容易逐行查看，却不会自动提供锁、完整提交或恢复功能。写入顺序、完成依据与后续读取规则都需要由程序明确实现。

## 学习起点与验证

从 [12.5 队列编辑与撤回](/content/chapter-12-task-control/05-manage-queue/README.md) 的完整 `src/` 继续。第 12 章练习增加的是验证脚本，没有另一份产品源码需要替换。

每一节都会把“保存或恢复成功”对应到可以观察的数据。本节先查看文件中的会话头与快照，核对消息、模式、清单和待处理队列各自保存了什么；之后再检验有效记录读取与恢复结果。能打开一个文件，只能证明存在一份记录，不能证明程序已经能用它恢复会话。

进入第一节时，在仓库根目录切换学习快照：

```bash
npm run lesson:13.1
```

然后启动 Agent：

```bash
hello-my-agent
```

也可以用第一节提供的 `--session-dir` 把演示记录放到独立目录，便于检查。每次启动会创建新的会话文件；本节尚不提供选择旧文件并继续对话的入口。
