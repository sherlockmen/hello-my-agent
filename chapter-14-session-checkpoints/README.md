# 第 14 章：会话分支与文件检查点

第 13 章让我们退出后还能接上讨论：消息、模式、任务清单和未交付要求保存在会话文件里，新的进程读回它们，等待下一条输入。但恢复讨论没有改变工作区里的文件。上次工具返回的 `src/add.ts` 是一份旧观察，当前磁盘上的文件可能已经不同。

本章继续使用加法小项目。原会话已经检查过负数与零相加，我们想再试一种方案：是否要拒绝 `NaN` 这样的输入。我们希望保留原来的讨论，也希望试改文件后能够检查变化、必要时恢复。两件事分别需要会话分支和文件检查点。

## 两种“回去”，改变的是不同对象

**会话分支**从一次已保存的讨论创建新的会话 ID。新讨论从复制的消息等状态开始，之后各自追加；原会话文件保持原样。但两次讨论仍可能指向同一个工作区，创建分支不会同时复制 `src/add.ts`。

**文件检查点**在 Agent 真正写文件前，先保存旧内容和预期的新内容。记录存在只说明恢复依据已经落盘，不代表随后的写入一定成功。恢复时，程序先核对当前文件是否等于预期的新内容，符合条件才恢复旧内容。有人后来又改过同一个文件时，程序要报告冲突，不能为了“回退”覆盖这些新修改。

| 我们想做的事 | 处理的对象 | 完成后能确认什么 |
| --- | --- | --- |
| 保留原讨论，另试一种想法 | 会话状态与新会话文件 | 新旧讨论有各自身份，后续保存不混在一起 |
| 查看 Agent 计划写入什么 | 旧内容、预期新内容与当前文件 | 哪次记录涉及哪个路径，当前文件是否符合预期 |
| 撤回一项已记录的文件修改 | 当前文件与文件检查点 | 当前内容符合恢复条件时，才恢复旧内容 |

这些操作都不能撤销已经发出的网络请求、安装过的软件或命令创建的所有文件。文件恢复只对本章明确记录的工具写入负责；恢复以后仍应读取当前文件并运行测试。
