# 第 27 章：让工具在可控范围内并行

模型一次请求读取入口文件、搜索测试，再读取配置；这些内容互不依赖，逐项等待会把时间相加。若直接把所有工具都交给 `Promise.all`，写入可能撞上还没结束的读取，取消后底层资源可能继续占用，倒序完成的结果也容易失去归属。

本章先把同时执行的范围收在明确的本地只读白名单内。相邻读取共享有限名额，写入、命令、技能加载、MCP、Web和委派工具构成串行屏障；每项仍经过原来的权限与参数检查。默认容量2，本地可设1到4；模型不能通过工具参数提高容量。外部程序仍可能改文件，所以并发读取不构成原子项目快照。

## 从一批调用到下一次模型请求

一批请求先固定sequence与callID。sequence让界面一直更新同一行，callID让模型知道结果属于哪次调用。容量满时同段其余读取排队；一项真正完成并收尾后，才把名额交给同段下一项。到写入等屏障时，先等前段全部结束，再执行屏障，随后才能开始后段。

排队与执行分别计时。只读项超时会形成自己的观察；已启动操作收到停止请求后仍要等真实返回与清理，再归还名额。整轮取消也等待同伴收尾，不会因为一只计时器到期就宣布资源已释放。

界面可以及时显示先完成的项目，下一次模型请求却要等整批观察收齐。结果按原调用顺序进入历史，普通错误保留原因与同伴成果，取消则为未启动项明确补入未执行说明。模型据此决定补读、修正参数或回答。

第26章的JobID跟踪一个可以跨轮存活的后台进程；本章的callID跟踪本轮一项工具观察。调度器名额覆盖的是调用领槽到结果收尾的时间，不会因启动一个后台作业就把那个进程永久计入本批容量。子任务、远端接口和有副作用操作也没有因为本章出现并发就获得重试或自动扩容的许可。
