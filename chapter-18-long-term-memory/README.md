# 第 18 章：保存可检查的长期记忆

昨天已经告诉 Agent“本项目测试命令是 `npm run test:unit`”，今天开一个新会话，它又问了一遍。第 13 章能恢复原来的对话，但我们不一定想把整段旧任务带回来；第 17 章的 `AGENTS.md` 适合维护项目规则，也不适合让模型在工作中随意改写。

本章增加一个专门保存少量项目事实的地方。用户可以明确保存，模型可以提出候选，之后还可以查看来源、纠正过期信息。每次新任务开始，程序读取当前有效条目，随请求交给模型。这里的“记住”是本地文件与请求组装的能力，不是改变模型权重。

## 从一句话到下一项任务的依据

我们始终使用同一个例子：`本项目测试命令是 npm run test:unit`。先由用户保存它，核对文件和来源；再让模型提议相同事实，观察批准与拒绝的分支；最后假设命令变化，纠正那条有 ID 的记录。

保存成功只证明文件已更新。下一项任务重新读取后，这句话才进入模型参考；模型是否据此提出正确命令、命令是否获准、测试是否通过，还要分别看请求、工具调用和实际结果。
