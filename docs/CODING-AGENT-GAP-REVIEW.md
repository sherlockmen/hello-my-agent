# CLI + TUI Agent 能力缺口复核

核对日期：2026-09-16。产品边界：可通过 npm 安装、在本地终端交互使用的 Coding Agent。主要参照 Claude Code、Codex CLI 和 Gemini CLI 的终端工作流。

**结论：保留现有 36 章主线，优先补齐终端交互与运行约定。** 原大纲已经包含输入、审批、取消、会话恢复、检查点、后台任务等机制；主要缺口是这些机制怎样在 TUI 中协同工作，以及用户怎样查看状态、介入任务和处理失败。下面八项是建议新增或细化的教学内容，不代表八个完全缺失的模块，也不直接对应八个新章节。

此前建议为浏览器、评审、PR/CI、非交互模式扩为约 40 章，范围偏宽。本次按用户明确的 CLI + TUI 边界修正：浏览器与 PR/CI 作为扩展工作流，本地代码评审和非交互运行继续属于主线；是否拆章由教学负担决定。

评估依据是 [课程规划](planning/COURSE.md)和[能力目标](planning/CAPABILITIES.md)。当前仅第一章代码已实现；本次只核对文档，没有运行厂商产品对比测试，也没有改动正式章号。

## 优先补充的八项内容

### T1 输入、焦点与运行中干预

**已有基础：** 第 08、11—12 章已经有取消、多行、粘贴、文件引用、审批、提问和输入队列。

**补充内容：** 输入撤销与历史搜索、文件和命令补全、调用外部编辑器；明确输入框、审批框、任务列表和子进程谁持有键盘焦点。运行时区分“立即打断并补充要求”和“排队作为下一项任务”，显示队列并允许编辑或撤回。说明取消当前请求、清空草稿、退出程序各自的行为；不承诺已经发生的写入会因打断而撤销。

Claude Code 文档描述终端编辑、历史搜索、文件补全与后台操作；Gemini CLI 文档列出输入排队、外部编辑器和焦点切换。这些说明终端交互本身需要明确的状态设计。[Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode)、[Gemini CLI 快捷键](https://geminicli.com/docs/reference/keyboard-shortcuts/)

**验收：** 模型输出时输入中文并粘贴多行代码，审批出现后不误提交草稿；修改队列中的要求后只执行新版本；取消后可继续输入。中文组合输入、不同终端的按键编码需要实际验证，不能仅凭组件支持文本输入就算通过。

### T2 长输出、会话浏览与终端恢复

**已有基础：** 第 10—11 章有布局、工具折叠、宽度变化和退出恢复；第 34—35 章有性能与平台验证。

**补充内容：** 回看历史时保持滚动位置，能回到最新输出；展开完整工具结果、复制文本、查看代码与 diff；状态栏显示正在运行、等待批准、后台任务、上下文与用量。渲染量和日志存储分别设限，避免流式日志拖慢键盘操作。支持纯文本/无颜色显示，不能仅用颜色表达成功或失败；处理日志中的终端控制序列，避免直接破坏界面。

**验收：** 长会话和持续日志下仍能操作输入、审批、滚动；中文、emoji、窄窗口与 resize 可读；正常退出及可捕获信号/异常后恢复输入模式和光标。强制杀进程无法保证清理，教程需给出手工恢复终端的方法。按实际测试记录 macOS、Linux、Windows/WSL、SSH/tmux 的支持范围。

### T3 可交互的命令会话与人工接管

**已有基础：** 第 07 章有 shell、超时和取消，第 26—27 章有后台任务与生命周期。

**补充内容：** 管道与 PTY 的差别、持续输入与 EOF、终端尺寸传递、前后台切换、用户把焦点交给命令再返回 Agent。区分模型工具调用和用户直接运行命令，明确后者的权限、日志和是否加入上下文。开发服务需要就绪判断、端口归属和进程树清理。

Gemini CLI 的终端界面公开了进入与离开 shell 输入焦点、查看和停止后台 shell 的操作。[Gemini CLI shell 操作](https://geminicli.com/docs/reference/keyboard-shortcuts/#app-controls)

**验收：** 一个测试命令等待输入时，用户能接管并返回聊天；长测试转后台后仍能跟进日志；取消本任务清理所属进程，保留用户预先启动的服务。等待输入应由明确交互状态或用户确认处理，不能依靠猜测输出字符串自动回答。

### T4 在终端中检查、评审和撤销代码改动

**已有基础：** 第 06 章有 diff，第 14 章有检查点，第 19、25 章有评审 Skill/角色，第 28 章有 Git 工作区隔离。

**补充内容：** TUI 中按文件查看本次任务改动，分别展示修改前审批和修改后的结果；选择工作区、提交或基准分支作为评审范围；发现包含文件、行号、证据和优先级。把评审、修改、检查点恢复做成含义明确的操作，保留用户原有变更。

Codex CLI 支持对未提交修改、提交或基准分支做只读评审，并返回优先级明确的发现。[Codex CLI 本地评审](https://learn.chatgpt.com/docs/codex/cli)

**验收：** 临时仓库同时存在用户修改和 Agent 修改；能看清差异，评审不写文件，恢复检查点遇到外部修改时给出冲突信息。历史评审绑定当时版本，不能自动作为后续改动的通过证据。本地主线做到可审阅结果；远端 PR 不作为这一能力的前提。

### T5 会话管理在 TUI 中可操作

**已有基础：** 第 13—14 章已有持久化、恢复、分支和文件检查点。

**补充内容：** 会话列表、命名、搜索、恢复、分支与导出；恢复前显示所属目录、分支/版本信息和未完成任务。把恢复对话、继续执行和恢复文件分开解释；会话保存不等于后台进程还活着。

Codex CLI 文档将保存会话的选择与恢复列为终端工作流。[Codex CLI 会话入口](https://learn.chatgpt.com/docs/codex/cli)

**验收：** 关闭程序后从列表找到任务；若目录不存在、分支已变或后台进程已退出，界面显示真实状态。另一个终端持有同一会话时按既定锁策略处理；恢复消息不重复执行工具。

### T6 配置、权限和扩展状态可查看、可诊断

**已有基础：** 第 02、05、17、20—21、23、31、33 章已有配置、权限、规则、扩展、多模型和隔离。

**补充内容：** 配置覆盖顺序和来源、模型选择与生效时机、有效权限范围、受信任项目、MCP 连接状态、已加载规则/Skill；提供清晰的配置诊断入口。凭据脱敏，项目 Hook/MCP 启动前判断信任；切换供应商时不能误用上一供应商凭据。显示估计用量与实际返回用量的区别。

**验收：** 缺少 Key、配置错误、MCP 断开、隔离不可用时，用户在终端能找到原因与处理方式；拒绝审批后记录清楚，后续调用遵守有效策略。运行中修改模型或权限时，说明对当前和下一次调用的影响。官方配置与信任依据见 [补充参考记录](CODING-AGENT-REFERENCES.md)。

### T7 CLI 输入输出与无终端运行约定

**已有基础：** 第 09—12 章保留非交互入口，能力清单已包含 JSON 输出。

**补充内容：** TTY 检测、参数与 stdin、文本/JSONL 输出、stdout/stderr 分工、稳定退出码、取消信号和无交互审批策略。定义无 TTY 时的模式选择，不启动会等待键盘的 TUI；管道输出中不混入动画、颜色和进度文本。支持帮助、诊断与 shell 补全，完整 SDK 以后按需要接入。

**验收：** 用脚本逐行解析事件；输入结束、输出管道提前关闭和无人审批都能按约定结束；成功、失败、取消和需批准可判定。TUI 与非交互入口调用同一核心和权限逻辑。[Gemini CLI 非交互模式](https://geminicli.com/docs/cli/headless/)

### T8 长任务的效率、停止条件与故障可见性

**已有基础：** 第 03、13、15—16、21、27、30、34—35 章已有循环上限、恢复、预算、压缩、工具发现、任务限制与评测。

**补充内容：** 工具 schema 按需加载、供应商支持时的 prompt cache 统计；压缩、重试倒计时、用量和预算在 TUI 可见；重复失败无进展时调整策略或停止。区分完成、失败、受阻、取消和部分完成，终态附带实际验证结果。

**验收：** 断流、限流、压缩失败、预算耗尽时保留草稿、现有成果和可恢复信息；退避等待中仍可取消；恢复不会重复写文件。缓存未知就标未知，模型说完成不能替代测试和需求验收。详细来源与验收设计见 [补充参考记录](CODING-AGENT-REFERENCES.md)。

## 扩展示例与范围

| 内容 | 在本书中的位置 |
| --- | --- |
| 浏览器自动化与页面验证 | CLI Agent 可以通过 MCP/工具使用浏览器，适合扩展示例；不作为本地 TUI 成型的前置要求 |
| PR、远端 CI 与评审反馈 | 作为 Git/工具接入后的可选工作流；本地 diff、评审、测试和保护已有修改留在主线 |
| Vim 键位、主题定制、桌面通知、语音 | 基础输入与状态可靠之后再增加；按实际需求选择 |
| IDE 补全、完整编辑器插件、云端任务平台、团队后台 | 后续独立产品方向 |

扩展案例仍复用既有工具、权限、会话和事件机制。它们能提高特定任务能力，但不能代替终端输入、任务干预、状态显示和恢复的验收。

## 对课程结构的建议

1. 保留 36 章正式大纲；优先将 T1—T2 加入第 09—12 章的交互设计和失败实验。若第 11 章负担过重，先拆分“输入与控制”和“渲染与终端兼容”，再确定新章号。
2. 将 T3—T8 分别落入上述相关章节。TUI 首次接入时已有的能力要可操作；会话、后台和扩展等新机制在对应章节增加自己的 TUI 入口。
3. 终端行为测试随功能加入：输入、焦点、resize、取消、退出清理、子进程和管道需要集成验证，不能只检查渲染快照。真实模型任务质量另行评测。
4. 每章继续保留完整可运行代码、练习答案和 [中文教学注释](AUTHORING.md#教学代码注释所有新增小节必需)，沿同一个产品逐步构建。

本文件是修订后的缺口分析；正式大纲与章号未修改，以上建议尚未实现。
