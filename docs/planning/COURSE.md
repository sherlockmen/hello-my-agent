# 连续课程大纲：36 章，从命令入口到完整发布

版本：v0.1，2026-09-16。以下是助手依据已确认目标和公开资料制定的章序方案，尚未实现。36 章用于控制每章理解负担，试写时允许继续拆分，不以删去重要能力维持章数。

前置要求是 TypeScript 基础和 Coding Agent 使用经验。书内不重复介绍搜索、读取或工具调用的产品表象，而是解释它们的内部机制；异步迭代、取消、React、Git worktree 等实现知识仍在首次使用处讲解。

所有章节继承上一章完整代码。表中的“复用”说明重点继承关系；每章的故障实验与验收不是等到第 35 章才补测试。

## 第一部分：先做出能完成一次编码任务的 Agent（01—08）

阶段产物：普通命令行里已经能读代码、确认修改、执行测试并根据结果继续，能够取消。

| 章 | 本章增加什么 | 复用前面的什么 | 失败实验与完成标准 |
| --- | --- | --- | --- |
| 01 从空目录到自己的命令 | TS、编译入口、help/version、npm bin、本地 tarball 安装 | 初始工程 | 在源码目录外启动安装后的命令；缺少开发依赖也能运行 |
| 02 接通模型并持续对话 | 配置、模型 SDK、多轮消息、最小错误提示和用量记录 | CLI 入口 | 缺少 Key 时提示如何配置且不泄漏密钥；第二轮能引用第一轮内容 |
| 03 第一个工具与 Agent Loop | read_file、工具参数校验、调用 ID、结果回传、循环上限 | 模型请求与消息列表 | 文件不存在、未知工具或错误参数能回传；循环能正常停止而非无限重试 |
| 04 让 Agent 找到代码 | 文件列表、glob、内容搜索、分段读取、忽略规则和结果上限 | 读取工具、主循环 | 大目录和大文件有界返回；找到工单筛选逻辑并引用文件位置 |
| 05 在执行前作出权限决定 | 统一 allow/ask/deny、项目边界、终端批准与拒绝 | 工具执行入口 | 同一请求先拒绝再批准，只有批准后才执行；不能靠提示词代替执行前检查 |
| 06 让 Agent 按你确认的内容修改文件 | 创建/编辑、明确匹配、内容变化检测、diff、最低限度的修改前备份 | 搜索、读取、权限 | 重复匹配和文件已变化时拒绝盲改；批准的修改和实际写入一致 |
| 07 执行测试并读取结果 | 受控 shell 子进程、cwd、输出上限、退出码、超时和基础取消；把第 04 章搜索后端迁移到 `rg --files` 与 `rg` | 工具、权限、修改 | 卡住的命令可停止；失败测试的输出进入下一轮；搜索保留既有工具契约并处理缺少 `rg`、退出码与正则语义差异；不把执行成功等同于需求完成 |
| 08 流式输出与任务中断 | 文本增量、工具参数分片组装、请求取消和本轮结束原因 | 主循环、命令取消 | 半截参数不执行工具；生成或命令中断后能够继续下一次输入 |

练习题方向（每题正式编写时均提供完整解答）：01 增加一个诊断选项；02 明确配置覆盖顺序；03 增加列目录工具；04 让模型可以缩小结果数量但不能超过本地硬上限；05 增加受保护文件规则；06 处理目标文本出现多次；07 区分超时和测试失败；08 处理工具参数尚未完整时断开连接。

阶段产物：具有聊天、工具过程、审批、任务列表和取消的终端交互；早期普通输出保留为非交互模式。

| 章 | 本章增加什么 | 复用前面的什么 | 失败实验与完成标准 |
| --- | --- | --- | --- |
| 09 为什么需要把执行过程通知界面 | text/tool/approval/finish 等小量明确事件，用户输入与执行分离 | 已有循环、审批和取消 | 用终端日志和模拟消费者看到同一执行过程；核心不依赖 React |
| 10 第一个真正可用的 TUI | Ink/React、消息和输入组件、状态、键盘与组件清理 | 事件与已有执行入口 | 从 TUI 完成与非交互模式相同的读改测任务；退出恢复终端 |
| 11 做好终端交互细节 | 多行、粘贴、历史、文件引用、工具折叠、审批、斜杠命令、宽度变化 | TUI 组件和事件 | 中文和长内容不会错位；拒绝、取消、resize 和持续输出后仍能输入 |
| 12 计划、执行与向用户提问 | Plan/执行模式、任务清单、问题交互、补充输入队列 | 权限、工具、TUI 状态 | Plan 模式在执行层禁止写入；补充要求在明确边界生效；任务清单更新可见 |

练习题方向：09 新增工具耗时通知；10 显示当前模型；11 处理审批时粘贴与普通输入的焦点；12 增加一次阻塞式澄清并正确恢复任务。

## 第三部分：长时间使用需要的会话与上下文（13—18）

阶段产物：会话可恢复、可分支，长任务可以压缩上下文，项目知识能够跨会话保留。

| 章 | 本章增加什么 | 复用前面的什么 | 失败实验与完成标准 |
| --- | --- | --- | --- |
| 13 保存与恢复会话 | 会话 ID、JSONL 记录、状态版本、锁和中断标记 | 消息、事件与任务状态 | 崩溃后恢复半写记录；已发生的文件写入不因重放对话重复执行；不确定操作要求核对 |
| 14 会话分支与文件检查点 | 会话副本、检查点索引、带当前内容校验的恢复 | 会话和修改前备份 | 分支不修改原记录；用户后来改过的文件不会被静默覆盖；说明 shell/远端副作用的边界 |
| 15 计算与控制上下文预算 | token 估计与实际用量、输出预留、大结果裁剪与外存引用 | 消息和有界工具输出 | 大日志不直接挤爆上下文；原始结果仍可定位；估计与计费用量分别展示 |
| 16 自动压缩并继续任务 | 历史摘要、保留近期对话、规则和未完成任务、失败回退 | 预算、会话、任务清单 | 摘要失败保留原记录；工具调用与结果成组处理；压缩后能继续完成原任务 |
| 17 项目说明与规则加载 | 项目根识别、说明文件、作用范围、来源和加载预算 | 上下文组装 | 在子目录启动时找到适用规则；冲突来源可见；项目文本不会改变硬性执行权限 |
| 18 可检查的长期记忆 | 显式保存、模型提出记忆、读取、修改、删除和来源记录 | 会话、规则、文件工具 | 新会话能用到有效记忆；过期内容可纠正；重要记忆写入可见且受控 |

练习题方向：13 修复末尾损坏日志的读取；14 恢复时检测外部修改；15 输出完整日志路径；16 增加压缩失败的回退；17 展示规则来源；18 让一条过期记忆失效。

## 每章正文固定结构

1. 上一章起点、这章结束后的演示、所需环境。
2. 一个真实问题：展示当前版本为什么需要新机制。
3. 必要概念和一张小型数据流图。
4. 小步修改：涉及文件、关键代码、每步运行结果。
5. 完整执行追踪：使用具体输入串起整条路径。
6. 失败实验：触发、证据、修复、再次验证。
7. 解释题与小练习。
8. **完整参考答案**：思路、完整文件或补丁、运行步骤、预期结果、易错点。链接在题目处可直接访问，无须完成练习后解锁。
9. 本章完成标签、上一章到本章的差异、下一章的正式起点。

## 章序检查结果

- 文件编辑之前已有权限入口；命令工具从引入时就包含输出限制和取消。
- TUI 接入前已有完整核心及事件边界；非交互入口继续存在。
- 子 Agent 前已有会话、上下文和权限；并行前已有后台任务与生命周期。
- 插件打包在 Skills/Hooks/MCP 之后；不会先教空的插件架构。
- 日志和测试随功能累积；书末章节集中展示诊断与评测方法。
- 第 1 章建立本地安装链，第 36 章验证整合后的正式发布链。
