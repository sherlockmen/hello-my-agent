# 第 36 章：安装、发布与升级

[全书目录](../README.md) · [36.1 安装包与补全](01-package-and-install/README.md) · [36.2 发布检查](02-release-gates/README.md) · [36.3 配置与会话升级](03-config-and-session-upgrade/README.md) · [练习与答案](EXERCISES.md)

前一章已经能用固定任务检查 Agent。现在我们把它交给另一台电脑：那里没有课程源码，没有开发依赖，也没有作者的全局链接。能够在仓库里执行，不足以证明读者拿到安装包后也能执行。

本章沿着一次真实交付往前走。先检查 tarball 实际装了哪些文件，在源码目录之外执行读文件、改文件和测试；再把这些检查放进发布前的固定步骤；最后处理更换版本后留下的配置和会话。每一步都保留可核对的产物，避免把“构建成功”“上传成功”“升级兼容”混成一句话。

| 小节 | 我们要解决的问题 | 完成后能核对的事实 |
| --- | --- | --- |
| 36.1 | 安装后的程序是否只靠自己的运行依赖工作？ | 真正的 tarball、临时安装目录、工作区修改和测试结果；Bash/Zsh 补全脚本。 |
| 36.2 | 如何在上传前重复发现同一类交付错误？ | 包内容检查、CI 模板、带版本的发布准备与章节标签操作。 |
| 36.3 | 新程序能否继续理解旧的本地数据？ | 配置先校验、备份、迁移；旧会话恢复信息，等用户提出新要求。 |

课程仓库仍保持 `private: true`。本章会真正打包、临时安装和验证；公开 npm 上传需要发布者选好包名、版本、账户和权限后亲自执行。配置的 v1/v2 示例在本章引入，之前使用的 `.env` 仍按原规则读取。

## 本章从哪里继续

三个小节各自保留完整 TypeScript 快照，36.1 接在 35.3 的完成版之后。安装仍复用第一章的构建与命令入口；评测仍调用第三十五章同一份运行内核，权限确认、真实退出码和错误结果都保留。

## 本章完成后的 Agent

读者可以从安装包运行 Agent、生成补全脚本、检查发布内容，并显式迁移连接配置。已有会话不随程序升级自动重放工具。公开包名、签名、跨平台发行和持续维护仍属于发布者需要承担的实际工作，不能由一次本地通过替代。
