# 第 29 章：共享任务与 Agent 消息

第 25 章让父 Agent 委派一次独立的只读调查，第 28 章又把会写文件的任务放到单独工作区。现在遇到另一类需求：同一问题可以拆成几项只读调查，两个子助手要分工，有的调查还要等前一项的发现。

例如，用户要检查登录流程。我们先并行调查“入口”和“校验”，再让“复核”基于前两项发现检查遗漏。程序需要知道哪项任务被谁拿走、哪一轮结果仍有效、前置失败时后续该等还是该停。把模型回答里的“我负责入口”当成归属，无法阻止另一个子助手同时接走它；所以本章加入一张由程序独占修改的共享登记表。

模型负责提出调查内容、阅读观察并组织答复；本地协调者负责认领、租约和终态。所有 worker 仍使用第 25 章独立会话与只读工具，不执行命令，也不写项目文件。第 28 章的工作区能力继续保留给父 Agent，两条路径不会自动混用。

| 小节 | 我们解决什么 | 读完能观察什么 |
| --- | --- | --- |
| [29.1 认领与租约](01-claim-and-lease/README.md) | 两个固定 worker 怎样各拿一项，怎样拒绝迟到结果 | 同步认领、递增 token、真实子会话与父模型工具结果 |
| [29.2 依赖与失联回收](02-dependencies-reclaim/README.md) | 前置未完成时等待，失败时阻塞，过期重试怎样与依赖相接 | 图验证、失败传播、等旧子会话清理后才重领 |
| [29.3 Agent 消息与确认](03-agent-messages/README.md) | 一项调查怎样留下有身份的消息，谁能确认 | 消息ID、本轮去重、独立ack与任务终态 |

这一章完成后，我们可以让两个只读子会话分工，把可定位的文件证据与各项状态交回父模型；界面也能分别展示任务ID、worker、租约轮次和子会话。`completed`只证明子循环正常结束、检查点关闭且取得至少一条成功只读工具的文件证据，不证明分析结论完整或代码通过测试。父模型仍要依据用户需求评估结果，缺少依据时继续调查或说明未完成。

当前协调者只活在一个CLI进程内。退出后，任务表、消息与去重表都会消失；子会话JSONL仍保存在本机，但这些记录不会恢复旧worker的控制权。我们没有在这里实现跨进程锁、崩溃后调度恢复，或项目副作用恰好执行一次。第30章继续讨论怎样让新的运行在指定时间启动，先把“当前这次运行”能负责到哪里讲清楚。
