# 第 21 章：通过 MCP 接入独立工具服务

我们想让模型查询接口文档。把查询放进 Hook，每次工具执行都会触发，模型却未必需要这项资料；写成新的内置工具，又要为每个服务修改 Agent。MCP 让独立服务描述自己提供的工具，本地程序把这些描述接入现有工具调用通道。

本章先连接同机运行的文档服务，再连接远端 HTTP 服务，最后补齐连接、取消和退出的收尾。模型决定何时提出查询；程序负责启用服务、建立连接、取得工具目录、审批调用并交回结果。

## 查询一次文档，需要哪几方协作

服务提供 `lookup_docs` 的用途、参数和执行结果。Agent 保存公开工具名与服务连接的对应关系，让模型看到 `mcp__docs__lookup_docs`。模型提出查询后，程序检查权限、请求用户批准后路由请求，服务执行后返回资料，下一次模型请求才能依据这份资料回答。

服务提供工具不等于服务提供权限；工具名称被发现也不代表连接永远可用。我们会分别验证工具描述、实际调用和连接资源的状态。
